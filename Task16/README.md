# ai-chat-go — Task16

Чат с ИИ через OpenAI-совместимый API с веб-интерфейсом в стиле плоского
мессенджера (бирюзовая тема). Написан на Go; внешняя зависимость —
**официальный MCP SDK** (`github.com/modelcontextprotocol/go-sdk`).

> Task16 — подключение **удалённых MCP-серверов** (Model Context Protocol,
> Streamable HTTP) к агенту чата. Приложение — **MCP-клиент-хаб**: одновременно
> держит несколько серверов, собирает их инструменты в общий список
> function-calling и **проксирует вызовы модели** в соответствующий сервер.
> По умолчанию подключены три открытых сервера:
>
> | Slug | Сервер | Инструменты |
> |---|---|---|
> | `vkusvill` | ВкусВилл (`mcp.vkusvill.ru/mcp`) — первый открытый MCP-сервер в российском e-commerce | 11: поиск товаров, КБЖУ и состав, магазины, аналоги, скидки, рецепты… |
> | `dubai` | Dubai Grocery Prices (`prices.brainy.ae/mcp`) — цены на продукты и стоимость жизни в ОАЭ | 19: сравнение корзин, цены магазинов, топливо, аренда, школа, налоги… |
> | `supershopping` | SuperShopping (`supershopping-mcp.atdev.ai/mcp`) — шопинг-ассистент | 8: поиск товаров, сравнение, подбор образов, аналитика рынка, checkout… |
>
> Модель вызывает инструменты MCP наравне с локальными `get_current_time` и
> `roll_dice`, не зная о существовании протокола. Взаимодействие видно в
> интерфейсе: блок **«MCP»** в сайдбаре — карточка на каждый сервер (индикатор,
> число инструментов, **сворачиваемый** список инструментов, **тумблер
> вкл/выкл** и пиктограмма **⟳** для переподключения); чипы источника в панели
> **«Шаги»** — «🛒 ВкусВилл · 340 мс», «🛒 Dubai Grocery Prices · 1,2 с»,
> «🕓 локально»; длинные результаты вызовов свёрнуты до 600 символов.
> Статус — `GET /api/mcp`; в терминале — команда `/tools`.
>
> Отказоустойчивость: недоступный при старте сервер не мешает остальным
> (warning в консоли), фоновый цикл **автопереподключается каждые 60 с**,
> вызов при лежащем сервере падает быстро (fail-fast 30 с). Выключенный
> тумблером (или не подключённый) сервер **не передаёт инструменты модели**.
> Read-only инструменты работают без авторизации; персональные (история
> заказов, личные скидки, корзина) требуют OAuth 2.0 + PKCE — их ошибка 401
> передаётся модели текстом, и она объясняет пользователю, что нужно
> зарегистрировать ИИ-агента на `vkusvill.ru/oauth/registration/`.

## Возможности

- Веб-чат в браузере: локальный сервер + страница-мессенджер (бирюзовая тема).
- Потоковый вывод (SSE) прямо в окно чата.
- Поддержка reasoning-моделей: трейс `reasoning`/`reasoning_content`
  не показывается, но считается «активностью» и не даёт оборвать долго
  думающую модель.
- История диалога на сервере; кнопка «Новый диалог» (очистка истории).
- **Список моделей обновляется автоматически** при загрузке страницы из
  `GET {AI_BASE_URL}/models`; не-чат модели (embeddings/reranker/whisper)
  отфильтровываются по имени. Если API недоступен — фолбэк на `AI_MODELS`
  или `DefaultModels`.
- **Резервный провайдер `[reserve]`**: независимый OpenAI-совместимый эндпоинт
  (по умолчанию OpenCode Zen / DeepSeek), отдельный от основного GPUStack.
  Включается, когда основной недоступен; в сайдбаре отображается пунктирным
  контактом.
- **Управление форматом ответа** из интерфейса: `text`, `json`, `jsonschema`,
  `jsonschema_structured` (strict), плюс `stop`-последовательность.
- Панель **«Детали»** (`GET /api/debug`): последний запрос/ответ, пошаговый лог
  «Шаги» (включая вызовы инструментов с параметрами и результатом), суммарное
  количество токенов и общее время, а также диагностика (ошибка API, «нет
  ответа», превышение лимита токенов, нарушение JSON-схемы).
- Ползунки **`max_tokens`** и допустимого **таймаута ответа** (5–30 с) в интерфейсе.
- Терминальный режим (`-cli`) и разовый запрос из командной строки.
- Системный промпт, смена модели, настройка лимита токенов и таймаута.
- Конфигурация через переменные окружения, файл `.env` или флаги.
- **Инструменты агента (function calling)** доступны модели в чате:
  `get_current_time(region)` — текущие дата/время в заданном регионе (IANA);
  `roll_dice()` — случайное целое от 1 до 6 (именно игральный кубик; для
  подбрасывания монеты модель отвечает случайно, без инструмента). Модель сама
  решает, когда их звать; выполнение и подстановка результата происходят
  автоматически, невидимо для пользователя.
- **Интеграция MCP** (`AI_MCP_URLS` / флаг `-mcp-urls`, по умолчанию все три
  сервера выше): официальный Go SDK (`modelcontextprotocol/go-sdk`), транспорт
  Streamable HTTP, `initialize`-рукопожатие при старте (серверы подключаются
  параллельно), `tools/list` → инструменты всех серверов попадают в общий
  список function-calling; вызовы маршрутизируются в сервер-владелец
  (`tools/call`) с ретраем при сбросе сессии. **Коллизии имён**: инструмент,
  встречающийся у нескольких серверов (например, `search_products` есть и в
  Dubai, и в SuperShopping), выдаётся модели с префиксом —
  `dubai__search_products` / `supershopping__search_products`; уникальные
  имена сохраняются как есть. MCP недоступен — приложение работает дальше без
  него (warning в консоли): клиент **автопереподключается каждые 60 с** и
  подменяет список инструментов после успеха; пиктограмма **⟳** на карточке
  сервера форсирует коннект вручную (`POST /api/mcp/reconnect`); вызов
  инструмента при недоступном сервере падает быстро (fail-fast 30 с после
  неудачи, таймаут вызова `AI_MCP_TIMEOUT`, по умолчанию 30 с).
- **Тумблер вкл/выкл на каждый MCP-сервер**: выключенный сервер отключается,
  его инструменты **исключаются из списка, передаваемого модели** (как и у
  любого неподключённого сервера), фоновое переподключение его не трогает;
  включение подключает сервер заново. `POST /api/mcp/toggle`
  (`{"slug": "dubai", "enabled": false}`).
- **Видимость MCP в UI**: блок «MCP» в сайдбаре — карточка на каждый сервер
  (зелёный/красный индикатор, название, число инструментов, **сворачиваемый
  список инструментов с описаниями — по умолчанию свёрнут**; выключенный
  сервер приглушён с пометкой «выкл»), `GET /api/mcp`; в панели «Шаги» — чип
  источника вызова с **названием сервера** («🛒 Dubai Grocery Prices · 340 мс»
  / «🕓 локально») и длинные результаты, свёрнутые до 600 символов с кнопкой
  «показать целиком».
- **Markdown-форматирование** сообщений: заголовки, маркированные/нумерованные
  списки, **таблицы GFM** (`| a | b |` + `|---|---|`), жирный/курсив/
  зачёркнутый, код (строчный и блочный), ссылки, цитаты.
- **Ползунок «Максимальное количество циклов»** (1–10, по умолчанию 6): сколько
  раундов модель может запрашивать инструменты (в одном раунде их может быть
  несколько — лимит на число раундов, а не на число вызовов).
- **Быстрые сообщения (блобы-группы)** над строкой ввода: «Локальные»,
  «Комбо», «ВкусВилл», «Dubai Grocery Prices», «SuperShopping» (MCP-группы
  выделены цветом темнее). Клик по блобу открывает **контекстное меню с
  тестовыми сообщениями** группы — клик по пункту отправляет его в чат.
  «Комбо» — запросы, требующие и локального инструмента, и MCP одновременно
  (например, «Сколько сейчас времени в Дубае? И сравни цены на молоко 1 литр
  в супермаркетах Дубая»).

### Веб-интерфейс

При запуске без аргументов клиент поднимает сервер на `http://127.0.0.1:5190`
и открывает его в браузере (бирюзовый мессенджер с пузырями сообщений). Если
порт занят, берётся следующий свободный. Сервер слушает только `127.0.0.1`,
переписка не покидает компьютер. Страница умеет:

- отправлять сообщения (Enter или кнопка с бумажным самолётиком);
- показывать ответ по мере поступления токенов (включая трейс reasoning), с
  **Markdown-разметкой** и таблицами;
- отправлять сообщения через **блобы-группы** над строкой ввода: клик
  открывает контекстное меню с тестовыми сообщениями группы;
- «Новый диалог» (кнопка «+» в шапке) — очистить историю на сервере;
- выбирать модель в боковом меню; список обновляется из `/api/models`, для
  основной и резервной модели;
- настраивать `max_tokens` (ползунок), таймаут ответа (5–30 с) и **максимальное
  количество циклов** (ползунок 1–10);
- менять ширину панелей перетаскиванием: граница между «Настройками» и чатом
  (панель «Настройки» расширяется за счёт области чата) и между чатом и
  «Деталями»;
- выбирать формат ответа (`text` / `json` / `jsonschema` /
  `jsonschema_structured`) и задавать `stop`-последовательность;
- смотреть «Детали» (запрос/ответ, пошаговый лог «Шаги», токены, время и
  диагностику) через `GET /api/debug`;
- после перезагрузки страницы история восстанавливается (`GET /api/history`).

Чтобы браузер не открывался автоматически, добавьте `-no-open`.

## Как это работает

Клиент отправляет `POST {AI_BASE_URL}/chat/completions` с заголовком
`Authorization: Bearer <AI_API_KEY>` и телом в формате OpenAI Chat Completions.
В потоковом режиме ответ читается как Server-Sent Events: строки `data: {...}`
разбираются, из `choices[].delta.content` собирается текст, `data: [DONE]`
завершает поток. Токены `choices[].delta.reasoning_content`/`reasoning`
(трейс думающей модели) не показываются, но регистрируются как активность,
чтобы не оборвать генерацию.

Веб-интерфейс работает так: браузер шлёт `POST /api/chat` с JSON
`{"message": "...", "format": ..., "maxTokens": ..., "timeout": ...,
"schema": ..., "stop": ...}`, сервер вызывает API и пересылает токены ответа
в тело HTTP-ответа по мере поступления; страница читает поток через
`ReadableStream` и дорисовывает текст в реальном времени. История хранится в
памяти сервера и отдаётся через `GET /api/history`.

Список моделей для сайдбара берётся из `GET {AI_BASE_URL}/models` и
фильтруется по имени (отбрасываются embedding/rerank/whisper/tts/audio/asr).
Если основной endpoint недоступен, используется резервный `[reserve]`, а для
фолбэка списка — `AI_MODELS`/`DefaultModels`.

Диагностика последнего обмена доступна через `GET /api/debug` и возвращает
детали для панели «Детали»: последний запрос, последний ответ, причину
приостановки (ошибка API, «нет ответа», превышение лимита токенов, нарушение
JSON-схемы), а также пошаговый лог `steps` (включая каждый вызов инструмента с
параметрами и результатом), суммарные `tokens`, `prompt_tokens`,
`completion_tokens` и `time_ms`.

## MCP: несколько серверов (Task16)

Главная фича Task16 — **MCP-хаб** (`mcpclient`): приложение одновременно
подключено к нескольким удалённым MCP-серверам и мостит их инструменты в
обычный function-calling цикл чата.

### Подключение и конфигурация

- Список серверов — переменная `AI_MCP_URLS` или флаг `-mcp-urls`: пары
  `slug=URL` через запятую. Пусто — список по умолчанию (vkusvill, dubai,
  supershopping); значение `off` полностью выключает MCP. Отображаемые имена
  известных slug подставляются автоматически.
- Транспорт — Streamable HTTP официального Go SDK
  (`github.com/modelcontextprotocol/go-sdk`), рукопожатие `initialize` +
  `tools/list` ограничены 15 с. Серверы подключаются **параллельно**; недоступный
  при старте сервер не мешает остальным — в консоль пишется warning, чат
  продолжает работать без его инструментов.
- Таймаут одного вызова инструмента — `AI_MCP_TIMEOUT` (по умолчанию 30 с).

### Маршрутизация вызовов

Модель видит инструменты всех серверов как обычные функции. Когда она их
вызывает, хаб знает, какому серверу принадлежит имя, и проксирует вызов
(`tools/call`), ограниченный таймаутом; результат возвращается модели текстом.
Чип в панели «Шаги» показывает сервер-источник и латентность. Если вызов упал
из-за сброса сессии, хаб один раз переподключается и повторяет запрос.

### Коллизии имён

Одинаковые имена у разных серверов запрещены протоколом function calling, поэтому:
уникальное имя остаётся как есть (`vkusvill_products_search`), а дубликаты
выдаются модели с префиксом slug — `dubai__search_products` и
`supershopping__search_products`. Префиксы пересчитываются при каждом
изменении набора подключённых серверов (отключился один — префиксы у общих
имён снимаются).

### Тумблер вкл/выкл и отказоустойчивость

- **Тумблер на карточке сервера** (`POST /api/mcp/toggle`): «выкл» отключает
  сессию и **убирает инструменты сервера из списка, передаваемого модели**,
  фоновое переподключение его не трогает; «вкл» подключает сервер заново.
  Состояние держится в памяти (до перезапуска приложения все включены).
  Неподключённый сервер (упал, dial не прошёл) тоже не передаёт инструменты —
  список модели всегда соответствует живым и включённым серверам.
- **Автопереподключение**: фоновый цикл каждые 60 с пытается подключить каждый
  включённый сервер без сессии; вручную — пиктограмма ⟳ на карточке
  (`POST /api/mcp/reconnect`, пустой slug = переподключить все).
- **Fail-fast**: после неудачного дial-а вызовы к этому серверу 30 с падают
  сразу («подождите или нажмите Переподключить»), не тратя таймаут; ручное
  переподключение и автопереподключение обходят ограничение.
- Сессии закрываются корректно (DELETE /mcp) при выходе — обработчик
  SIGINT/SIGTERM.

### API статуса

| Запрос | Ответ |
|---|---|
| `GET /api/mcp` | `{"servers":[{slug,name,url,enabled,connected,server,version,protocol,count,tools[],error}]}` — статус и инструменты каждого сервера. |
| `POST /api/mcp/reconnect` `{"slug":"dubai"}` | Переподключить один сервер (пустой slug — все); ответ — свежий статус. |
| `POST /api/mcp/toggle` `{"slug":"dubai","enabled":false}` | Включить/выключить сервер; ответ — свежий статус. |

## Инструменты агента (function calling)

Модель в этом чате умеет вызывать локальные инструменты, когда это уместно.
Инструменты описываются как OpenAI-совместимые `tools` в запросе к
`/chat/completions`; когда модель запрашивает вызов, сервер выполняет его
локально (не обращаясь к API) и подставляет результат обратно в диалог, после
чего модель продолжает генерацию. Весь обмен проходит внутри одного ответа —
пользователь видит только итоговый текст.

Доступные инструменты:

| Инструмент | Параметры | Результат |
|---|---|---|
| `get_current_time` | `region` (string) — IANA-таймзона, например `Europe/Moscow` | Текущие дата и время в регионе (`2006-01-02T15:04:05Z07:00 (Europe/Moscow)`). |
| `roll_dice` | — | Случайное целое от 1 до 6 (именно игральный кубик d6), каждое с равной вероятностью. |

К ним в веб-чате, CLI и разовом запросе динамически добавляются инструменты
всех подключённых MCP-серверов (см. «MCP: несколько серверов») — модель
смешивает их в одном диалоге: может узнать время локальным инструментом и тут
же сравнить цены на молоко через Dubai Grocery Prices.

Как это работает:

- `tools/tools.go` описывает инструменты (`Definitions`), исполняет их
  (`Execute`) и крутит цикл вызова (`RunLoop`): пока модель запрашивает
  инструменты, они выполняются и их результат возвращается модели. Число
  раундов ограничено: в интерфейсе — ползунком «Максимальное количество
  циклов» (1–10), вне интерфейса — `maxToolRounds` (6).
- `api/client.go` передаёт `tools` в запросе и умеет собирать фрагментированные
  `tool_calls` из потока (SSE).
- Инструменты доступны и в веб-чате, и в CLI чате (`go run ./app` /
  `go run ./app -cli`), а также в разовом запросе.

Примеры:

```sh
go run ./app "Сколько сейчас времени в Токио?"
go run ./app "Брось кубик"
go run ./app "Найди во ВкусВилле творог 5% и покажи КБЖУ"          # через MCP ВкусВилла
go run ./app "Сколько сейчас времени в Дубае? И сравни цены на молоко"  # локальный инструмент + MCP
```

## Безопасность

- `.env`, `.idea/` и `bin/` уже в `.gitignore` в корне проекта — это правило
  действует для всех папок задач, поэтому секреты и артефакты не попадают в
  репозиторий.
- Не передавайте ключ флагом `-api-key` в общих системах: он остаётся в истории
  shell.
- Приложение не пишет ключ и переписку на диск; детали запроса/ответа хранятся
  только в памяти и отдаются в панель «Детали», сам ключ в них не попадает.
