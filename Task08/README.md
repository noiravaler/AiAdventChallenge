# ai-chat-go — Task08

Чат с ИИ через OpenAI-совместимый API с веб-интерфейсом в стиле плоского
мессенджера (бирюзовая тема). Написан на Go без внешних зависимостей: только
стандартная библиотека.

> Task08 — продолжение чата с **инструментами (function calling)**,
> **Markdown-форматированием** и **сохранением контекста диалога**, дополненное
> **учётом токенов**: панель **«Количество токенов»** с метрикой **«Токены
> истории диалога»**, токены по каждому раунду в панели «Шаги» и **вложения «+»**
> — готовые тексты (150 000 и 300 000 токенов) для воспроизведения конкретных
> текстовых кейсов.
>
> Реализованы: панель **«Количество токенов»** (токены запроса/ответа, время,
> токены истории диалога с подсказкой ⓘ), **токены по шагам** («Раунд N»
> показывает prompt/completion своего API-вызова), **меню «+» у поля ввода** с
> пунктами «Текст 150 000 токенов» и «Текст 300 000 токенов», а также понятные
> русскоязычные ошибки для слишком больших/некорректных запросов с показом
> блока «Ошибка» в «Деталях».

## Возможности

- Веб-чат в браузере: локальный сервер + страница-мессенджер (бирюзовая тема).
- Потоковый вывод (SSE) прямо в окно чата.
- Поддержка reasoning-моделей: трейс `reasoning`/`reasoning_content`
  не показывается, но считается «активностью» и не даёт оборвать долго
  думающую модель.
- История диалога на сервере; кнопка «Новый диалог» (очистка истории).
- **Список моделей обновляется автоматически** при загрузке страницы из
  `GET {AI_BASE_URL}/models`; не-чат модели (embeddings/reranker/whisper)
  отфильтровываются по имени. Если API недоступен — фолбэк на `AI_MODELS`
  или `DefaultModels`.
- **Резервный провайдер `[reserve]`**: независимый OpenAI-совместимый эндпоинт
  (по умолчанию OpenCode Zen / DeepSeek), отдельный от основного GPUStack.
  Включается, когда основной недоступен; в сайдбаре отображается пунктирным
  контактом.
- **Управление форматом ответа** из интерфейса: `text`, `json`, `jsonschema`,
  `jsonschema_structured` (strict), плюс `stop`-последовательность.
- Панель **«Детали»** (`GET /api/debug`) с блоками:
  - **«Запрос»** — JSON последнего запроса;
  - **«Шаги»** — пошаговый лог обмена; каждый шаг «Раунд N» показывает токены
    своего API-вызова («Токены: запрос X · ответ Y»), шаги инструментов —
    имя, параметры и результат (без токенов);
  - **«Количество токенов»** — «Токены запроса» (сумма prompt всех раундов),
    «Токены ответа» (сумма completion), «Токены истории диалога» (см. ниже,
    с подсказкой по наведению на ⓘ) и «Время»;
  - **«Ошибка»** — диагностика последней ошибки (ошибка API, «нет ответа»,
    превышение лимита токенов, нарушение JSON-схемы, некорректный/слишком
    большой запрос). Показывается только после реальной ошибки в текущей
    сессии; при загрузке страницы и смене модели не поднимается из старого
    состояния сервера.
- Ползунки **`max_tokens`** («Ответ модели») и допустимого **таймаута ответа**
  (5–30 с) в интерфейсе.
- **Вложения «+» слева от поля ввода**: всплывающее меню с готовыми текстами
  для воспроизведения конкретных текстовых кейсов — «Текст 150 000 токенов» и
  «Текст 300 000 токенов»; выбранный текст копируется в поле сообщения
  (`GET /api/sample?tokens=150|300`). Меню закрывается кликом вне его и по
  Escape.
- **Понятные ошибки больших запросов**: тело `POST /api/chat` принимается до
  64 МБ (большая вставка JSON-экранируется и вырастает в несколько раз); при
  превышении — «Сообщение слишком большое», при невалидном JSON — причина
  разбора; обе ошибки попадают и в чат, и в блок «Ошибка» «Деталей».
- Терминальный режим (`-cli`) и разовый запрос из командной строки.
- Системный промпт, смена модели, настройка лимита токенов и таймаута.
- Конфигурация через переменные окружения, файл `.env` или флаги.
- **Инструменты агента (function calling)** доступны модели в чате:
  `get_current_time(region)` — текущие дата/время в заданном регионе (IANA);
  `roll_dice()` — случайное целое от 1 до 6 (именно игральный кубик; для
  подбрасывания монеты модель отвечает случайно, без инструмента). Модель сама
  решает, когда их звать; выполнение и подстановка результата происходят
  автоматически, невидимо для пользователя.
- **Markdown-форматирование** сообщений: заголовки, маркированные/нумерованные
  списки, жирный/курсив/зачёркнутый, код (строчный и блочный), ссылки, цитаты.
- **Ползунок «Максимальное количество циклов»** (1–10, по умолчанию 6): сколько
  раундов модель может запрашивать инструменты (в одном раунде их может быть
  несколько — лимит на число раундов, а не на число вызовов).
- **Быстрые сообщения (блобы)** над строкой ввода: клик отправляет готовую фразу
  («Хочу узнать время в Сиднее», «Брось кубик», «Кинь монетку», «Время в Монако
  и кинь кости 2 раза»).
- **Сохранение контекста диалога между перезапусками**: история, выбранная
  модель и размер истории (токены) автоматически записываются в отдельный файл
  на каждую модель в папке `history/` (по умолчанию
  `history/.chat-history-<модель>.json`) и восстанавливаются при запуске.
  См. «Сохранение контекста» ниже.

### Веб-интерфейс

При запуске без аргументов клиент поднимает сервер на `http://127.0.0.1:5190`
и открывает его в браузере (бирюзовый мессенджер с пузырями сообщений). Если
порт занят, берётся следующий свободный. Сервер слушает только `127.0.0.1`,
переписка не покидает компьютер. Страница умеет:

- отправлять сообщения (Enter или кнопка с бумажным самолётиком);
- показывать ответ по мере поступления токенов (включая трейс reasoning), с
  **Markdown-разметкой**;
- отправлять сообщения кликом по **блобам** над строкой ввода;
- вставлять **готовые тексты-вложения** через меню кнопки **«+»** слева от поля
  ввода («Текст 150 000 токенов», «Текст 300 000 токенов»);
- «Новый диалог» (кнопка «+» в шапке) — очистить историю на сервере;
- выбирать модель в боковом меню; список обновляется из `/api/models`, для
  основной и резервной модели;
- настраивать `max_tokens` (ползунок), таймаут ответа (5–30 с) и **максимальное
  количество циклов** (ползунок 1–10);
- выбирать формат ответа (`text` / `json` / `jsonschema` /
  `jsonschema_structured`) и задавать `stop`-последовательность;
- смотреть «Детали» (запрос/ответ, пошаговый лог «Шаги» с токенами раундов,
  «Количество токенов», время и диагностика) через `GET /api/debug`;
- после перезагрузки страницы история восстанавливается (`GET /api/history`).

Чтобы браузер не открывался автоматически, добавьте `-no-open`.

## Как это работает

Клиент отправляет `POST {AI_BASE_URL}/chat/completions` с заголовком
`Authorization: Bearer <AI_API_KEY>` и телом в формате OpenAI Chat Completions.
В потоковом режиме ответ читается как Server-Sent Events: строки `data: {...}`
разбираются, из `choices[].delta.content` собирается текст, `data: [DONE]`
завершает поток. Токены `choices[].delta.reasoning_content`/`reasoning`
(трейс думающей модели) не показываются, но регистрируются как активность,
чтобы не оборвать генерацию.

Веб-интерфейс работает так: браузер шлёт `POST /api/chat` с JSON
`{"message": "...", "format": ..., "maxTokens": ..., "timeout": ...,
"schema": ..., "stop": ...}`, сервер вызывает API и пересылает токены ответа
в тело HTTP-ответа по мере поступления; страница читает поток через
`ReadableStream` и дорисовывает текст в реальном времени. История хранится на
сервере и отдаётся через `GET /api/history`; кроме того, она сохраняется на диск
между перезапусками — см. «Сохранение контекста» ниже.

Список моделей для сайдбара берётся из `GET {AI_BASE_URL}/models` и
фильтруется по имени (отбрасываются embedding/rerank/whisper/tts/audio/asr).
Если основной endpoint недоступен, используется резервный `[reserve]`, а для
фолбэка списка — `AI_MODELS`/`DefaultModels`.

Диагностика последнего обмена доступна через `GET /api/debug` и возвращает
детали для панели «Детали»: последний запрос, последний ответ, причину
приостановки (ошибка API, «нет ответа», превышение лимита токенов, нарушение
JSON-схемы), а также пошаговый лог `steps` (каждый раунд — со своими
`prompt_tokens`/`completion_tokens`, каждый вызов инструмента — с параметрами
и результатом), суммарные `tokens`, `prompt_tokens`, `completion_tokens`,
`history_tokens` и `time_ms`.

## Токены истории диалога

Метрика **«Токены истории диалога»** в блоке «Количество токенов» показывает
примерный размер текущего диалога без учёта транзитных обменов инструментами:

```
prompt первого раунда (вся история + новое сообщение) + completion финального ответа
```

Пример: раунд 1 — prompt 292 / completion 35 (вызов инструмента), раунд 2 —
prompt 327 / completion 18 (финальный ответ). Тогда история =
292 + 18 = **310** токенов; промежуточный tool-обмен (35 токенов completion и
повторная отправка истории в раунде 2) в счёт не идёт.

- После каждого обмена значение **заменяется**, а не суммируется: новый запрос
  уже содержит всю историю.
- Значение хранится в файле истории модели (`history_tokens`), восстанавливается
  при запуске, переносится при смене модели и сбрасывается кнопкой «Новый
  диалог».
- В блоке «Количество токенов» рядом с метрикой есть подсказка (ⓘ) с описанием
  формулы.

## Вложения «+» (текстовые кейсы)

Кнопка **«+»** слева от поля ввода открывает меню с готовыми текстами —
вложениями для воспроизведения конкретных текстовых кейсов (большие промпты,
проверка лимитов контекста и т.п.):

| Пункт меню | Источник | Endpoint |
|---|---|---|
| «Текст 150 000 токенов» | `server/static/150_000.txt` (вшит через `go:embed`) | `GET /api/sample?tokens=150` |
| «Текст 300 000 токенов» | `server/static/300_000.txt` (вшит через `go:embed`) | `GET /api/sample?tokens=300` |

Выбранный текст загружается с сервера и вставляется в поле сообщения. Оба
файла — нейтральные тексты на тему погоды (~149k и ~298k токенов
соответственно); при необходимости их можно заменить своими кейсами с теми же
именами файлов.

Если сообщение слишком большое (тело `POST /api/chat` больше 64 МБ) или не
разбирается как JSON, сервер возвращает понятную русскоязычную ошибку и
заполняет блок «Ошибка» в панели «Детали».

## Сохранение контекста (истории)

Веб-чат сохраняет диалог между перезапусками, чтобы после остановки и запуска
приложение продолжило беседу с того места, где остановились. Состояние каждого
агента (модели) пишется в отдельный файл внутри папки `history/`, путь которой
задаётся переменной `AI_HISTORY_FILE` (по умолчанию `history/.chat-history.json`).

Файл содержит JSON следующего вида:

```json
{
  "model": "default-chat",
  "history_tokens": 310,
  "messages": [
    { "role": "user", "content": "Привет!" },
    { "role": "assistant", "content": "Здравствуйте!" }
  ]
}
```

Как это работает:

- **Что хранится** — реплики диалога (пользователь и ассистент), в том числе
  промежуточные вызовы инструментов и их результаты, текущая выбранная модель
  и размер истории в токенах (`history_tokens`). Системный промпт не
  сохраняется и пересоздаётся из текущей конфигурации при запуске, поэтому если
  он поменялся, новый применится заново.
- **Когда пишется** — после каждого изменения истории: завершённого обмена
  репликами, новой модели и очистки («Новый диалог»). Если запрос к модели
  завершился ошибкой, незавершённый ход пользователя отбрасывается и это
  состояние тоже сохраняется.
- **Когда читается** — при старте сервера (`server.New` → `restore`): если файл
  есть, реплики добавляются в историю, а выбранная модель восстанавливается
  (если она по-прежнему доступна в списке).
- **Формат** — переносимое сообщение `role`/`content` в точности как в API
  (`tools`/`tool_calls`/`tool_call_id`/`at`). См. пример ниже.
- **Очистка устаревшего** — при старте и при обновлении списка моделей из
  файлов удаляются сообщения старше 3 дней (`historyRetention = 3 * 24h`); если
  в файле не осталось сообщений в пределах окна (или он вовсе устарел) — файл
  удаляется целиком. Папка `history/` исключена из git.

Независимо от файла на диске, временные данные панели «Детали» (последний
запрос/ответ, шаги, токены, время, ошибка) хранятся только в памяти и в файл
не попадают.

## Инструменты агента (function calling)

Модель в этом чате умеет вызывать локальные инструменты, когда это уместно.
Инструменты описываются как OpenAI-совместимые `tools` в запросе к
`/chat/completions`; когда модель запрашивает вызов, сервер выполняет его
локально (не обращаясь к API) и подставляет результат обратно в диалог, после
чего модель продолжает генерацию. Весь обмен проходит внутри одного ответа —
пользователь видит только итоговый текст.

Доступные инструменты:

| Инструмент | Параметры | Результат |
|---|---|---|
| `get_current_time` | `region` (string) — IANA-таймзона, например `Europe/Moscow` | Текущие дата и время в регионе (`2006-01-02T15:04:05Z07:00 (Europe/Moscow)`). |
| `roll_dice` | — | Случайное целое от 1 до 6 (именно игральный кубик d6), каждое с равной вероятностью. |

Как это работает:

- `tools.go` описывает инструменты (`Definitions`), исполняет их
  (`Execute`) и крутит цикл вызова (`RunLoop`): пока модель запрашивает
  инструменты, они выполняются и их результат возвращается модели. Число
  раундов ограничено: в интерфейсе — ползунком «Максимальное количество
  циклов» (1–10), вне интерфейса — `maxToolRounds` (6).
- `api/client.go` передаёт `tools` в запросе и умеет собирать фрагментированные
  `tool_calls` из потока (SSE).
- Инструменты доступны и в веб-чате, и в CLI чате (`go run ./app` /
  `go run ./app -cli`), а также в разовом запросе.

Примеры:

```sh
go run ./app "Сколько сейчас времени в Токио?"
go run ./app "Брось кубик"
```

## Безопасность

- `.env`, `.idea/` и `bin/` уже в `.gitignore` в корне проекта — поэтому секреты
  и артефакты не попадают в репозиторий.
- Не передавайте ключ флагом `-api-key` в общих системах: он остаётся в истории
  shell.
- Приложение не хранит **API-ключ** на диске и не включает его в файл истории.
  Детали запроса/ответа для панели «Детали» живут только в памяти. Единственное,
  что пишется на диск, — **переписка** в файлы контекста в папке `history/`
  (`history/.chat-history-<модель>.json`), чтобы диалог сохранялся между
  перезапусками. Учтите: эти файлы содержат текст беседы в открытом виде; при
  необходимости держите их вне репозитория и не публикуйте.
