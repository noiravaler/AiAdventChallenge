# AI Challenge — workspace

Репозиторий-песочница для тестовых заданий **AI Challenge**. Каждая подпапка
`TaskNN` — отдельное тестовое задание со своей структурой и своим детальным
README.

## Текущие задания

| Папка    | Описание                                                            |
| -------- | ------------------------------------------------------------------- |
| `Task01` | Чат-клиент для общения с ИИ по OpenAI-совместимому API (GPUStack). |
| `Task02` | Расширенный чат-клиент: резервный провайдер, reasoning-модели, форматы ответа, панель «Детали», авто-обновление списка моделей. |
| `Task03` | Решатель задач: список задач, запуск решения несколькими способами, два уровня рассуждения (low/high), блок «Вывод» с анализом, гибкая проверка ответа. |
| `Task04` | Эксперимент с настройками модели: две задачи рядом, матрица «Результаты» (3 температуры × 5 прогонов), проверка ответа для задачи 1, блоки «Вывод» и «Общий вывод», повтор при ошибке/таймауте. |

## Task01 — AI-чат

Go-приложение без внешних зависимостей (`go 1.22`, только стандартная
библиотека). Умеет:

- общаться с любым OpenAI-совместимым endpoint по `POST {AI_BASE_URL}/chat/completions`;
- работать в терминале (`-cli`), послать один запрос (`ai-chat "промпт"`) или
  служить локальной веб-страницей в стиле мессенджера (режим по умолчанию);
- стримить ответ по SSE и писать запросы/ответы в консоль в виде JSON-строк.

Структура: `app` (клиент), `server` (веб-сервер), `api` (HTTP-клиент API),
`config` (конфигурация). Подробнее — в [Task01/README.md](Task01/README.md).

## Task02 — AI-чат (расширенный)

То же приложение, что и Task01, с дополнительными возможностями:

- **резервный провайдер `[reserve]`** — независимый OpenAI-совместимый эндпоинт
  (по умолчанию OpenCode Zen / DeepSeek), отдельный от основного GPUStack,
  включается, когда основной недоступен;
- **поддержка reasoning-моделей** (`reasoning`/`reasoning_content`) — трейс
  думающей модели не показывается, но считается «активностью» и не даёт оборвать
  долгую генерацию;
- **управление форматом ответа** — `text`, `json`, `jsonschema`,
  `jsonschema_structured` (strict) и `stop`-последовательность из интерфейса;
- **панель «Детали»** (`GET /api/debug`) — последний запрос/ответ и диагностика
  (ошибка API, «нет ответа», превышение лимита токенов, нарушение JSON-схемы);
- **ползунки `max_tokens` и таймаута** ответа (5–30 с) в веб-интерфейсе;
- **динамический список моделей** — обновляется из `GET {AI_BASE_URL}/models`,
  не-чат модели отсекаются, фолбэк — `AI_MODELS`/`DefaultModels`.

Запуск, флаги и общая структура — как в Task01. Подробнее —
в [Task02/README.md](Task02/README.md).

## Task03 — Решатель задач

То же приложение, расширенное до инструмента решения задач:

- **список задач** — выпадающий список условий; при выборе заполняются
  «Условие» и «Ожидаемый ответ»;
- **способы решения** — прямой ответ, пошаговое решение, «через промпт»
  (модель сначала составляет промпт), эксперт (отдельный запуск на каждого
  выбранного эксперта: Математик / Философ / Критик);
- **уровень рассуждения** — выбранные способы запускаются автоматически для
  двух уровней (`low` и `high`), результаты в двух вкладках-таблицах внутри
  блока «Решения»;
- **блок «Вывод»** — после завершения всех запусков модель анализирует
  результаты (затраты ресурсов, сравнение методов, оправданность затрат,
  рекомендацию) и формирует заключение;
- **гибкая проверка ответа** — успех определяется с учётом разных написаний,
  LaTeX-символов, дробей и объяснений;
- **таймаут запуска** (10–60 с) с обрывом незавершённых процессов и
  отображением причины в «Деталях»;
- **лимит токенов 20000** для ответов.

Запуск, конфигурация и структура — как в Task02. HTTP-эндпоинты решения:
`POST /api/solve` (один запуск) и `POST /api/conclusion` (итоговый вывод).
Подробнее — в [Task03/README.md](Task03/README.md).

## Task04 — Эксперимент с настройками модели

Task04 развивает идею Task03, но фокусируется на **сравнении повторных
прогонов при разных температурах** для двух задач:

- **две задачи рядом** — слева блок выбора модели, правее `Задача 1` (логическая
  задача про высказывания А/Б/В, с проверкой ответа) и `Задача 2` (генеративная,
  например название книги, без проверки);
- **выбор модели** — список чат-моделей (основные + `[reserve]`), клик
  переключает модель через `POST /api/model`; список сохраняется целиком;
- **матрица «Результаты»** — для каждой задачи таблица `3 × 6`: температуры
  `0 / 0.7 / 1.2`, по 5 прогонов на каждую; зелёная ячейка при совпадении
  ответа, красная — иначе (для задачи 1);
- **блок «Вывод» (на задачу)** — анализ прогонов по трём вопросам: отличия
  между прогонами, сбои формата/неверные ответы, где разнообразие полезно,
  а где вредит;
- **блок «Общий вывод»** — после обеих задач модель отвечает, какая настройка
  подходит какой задаче и даёт ли `temperature = 0` одинаковый ответ каждый раз;
- **повтор при ошибке/таймауте** — до 3 попыток с паузой 250 мс;
- **лимит токенов 15000** для таблицы результатов и таймаут одного запроса
  **30 с** по умолчанию.

Запуск, конфигурация и структура — как в Task02/Task03 (источник конфигурации
`../Task02/.env`). Эндпоинты: `POST /api/run`, `/api/run-conclusion`,
`/api/general-conclusion`, `/api/models`, `/api/model`.
Подробнее — в [Task04/README.md](Task04/README.md).

## Стек

- Go 1.22, только стандартная библиотека.
- HTTP-клиент, Server-Sent Events, встроенная static-страница (`go:embed`).
- Конфигурация: `.env` + переменные окружения (`AI_API_KEY`, `AI_BASE_URL`,
  `AI_MODEL`, `AI_SYSTEM`, `AI_TIMEOUT`, `AI_MAX_TOKENS`).

## Как запустить

```sh
cd Task01
go run ./app           # веб-чат (откроется браузер)
go run ./app -cli      # терминальный режим
go build -o bin/ai-chat ./app
```

> Секреты в `.env` исключены через корневой `.gitignore` и не попадают в
> репозиторий.
