# ai-chat-go — Task03

Веб-приложение для решения задач с помощью ИИ через OpenAI-совместимый API,
написанное на Go без внешних зависимостей (только стандартная библиотека).

> Task03 — приложение-инструмент для решения задач. Оно объединяет список
> задач, запуск решения несколькими способами, два уровня «рассуждения»
> (low / high) с отдельными таблицами результатов, блок «Вывод» с анализом
> всех решений, гибкую проверку ответа, таймаут выполнения и увеличенный
> лимит токенов.

## Возможности

- **Список задач** — выпадающий список условий задачи; при выборе заполняются
  поле «Условие» и «Ожидаемый ответ».
- **Способы решения** — выберите один или несколько способов (`Способы решения`):
  - *Прямой ответ* — модель решает задачу «как есть»;
  - *Пошаговое решение* — в промпт добавляется «решай пошагово»;
  - *Через промпт* — модель сначала составляет промпт для решения, затем
    решает по нему;
  - *Эксперт* — решение запускается отдельно для каждого выбранного эксперта
    (Математик, Философ, Критик); персона эксперта подставляется в системное
    сообщение.
- **Уровень рассуждения** — выбранные способы автоматически запускаются для
  **двух уровней**: `reasoning.effort: low` и `reasoning.effort: high`.
  Результаты показываются в двух вкладках-таблицах внутри блока «Решения».
- **Таблица «Решения»** — по одному ряду на каждый запуск: наименование
  способа, токены, время, успех (зелёная галочка / красный крестик / иконка
  стоп при таймауте / иконка ошибки) и раскрывающиеся «Детали» с ходом
  решения модели.
- **Таймаут** — ползунок от 10 с до 1 минуты (по умолчанию 10 с). По
  превышении незавершённые запуски обрываются и попадают в таблицу с иконкой
  стоп и причиной в «Деталях».
- **Блок «Вывод»** — после завершения всех решений модель анализирует
  полученные результаты и делает вывод: суммарные затраченные ресурсы по всем
  решениям и по каждому уровню рассуждения, сравнение способов решения между
  собой, оправданность затрат относительно результата и рекомендация
  итогового способа и уровня рассуждения.
- **Гибкая проверка ответа** (`/api/solve`) — ответ сравнивается с ожидаемым
  с учётом разных написаний, LaTeX-символов (например `\frac`, `\Rightarrow`),
  дробей и объяснений; для числовых/координатных ответов допускается
  эквивалентность значений.
- **Лимит токенов 20000** — `max_tokens` ответа по умолчанию увеличен до
  20000, чтобы думающие модели успевали выдать и рассуждение, и финальный
  ответ.
- **Локальный сервер с `go:embed`** — страница чата встроена в бинарник,
  поэтому любые правки `static/index.html` требуют пересборки.
- **Резервный провайдер** — при недоступности основной модели используется
  резервный провайдер `[reserve]`; список моделей, reasoning-модели, форматы
  ответа, панель «Детали» и авто-обновление списка моделей доступны из коробки.

## Требования

- Go 1.22 или новее.

## Быстрый старт

```sh
cd Task03
cp .env.example .env
# откройте .env и впишите AI_API_KEY

```

Или без файла `.env`:

```sh
export AI_API_KEY="sk-..."
go run ./app
```

> Примечание: репозиторий Task03 не содержит `.env` — создайте свой файл по
> образцу `.env.example` (или задайте переменные окружения). Секреты в `.env`
> исключены через корневой `.gitignore`.

## Настройка

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AI_API_KEY` | — | API-ключ. Не нужен для локального сервера. |
| `AI_BASE_URL` | `https://api.openai.com/v1` | Базовый URL API (без `/chat/completions`). |
| `AI_MODEL` | `gpt-4o-mini` | Имя основной модели. |
| `AI_MODELS` | `DefaultModels` | Явный список моделей для бокового меню (фолбэк). |
| `AI_SYSTEM` | — | Системный промпт. |
| `AI_TIMEOUT` | `5m` | Таймаут одного запроса, например `90s`. |
| `AI_MAX_TOKENS` | `0` | Максимум токенов ответа; `0` → 20000. |
| `AI_RESERVE_BASE_URL` | `https://opencode.ai/zen/v1` | Базовый URL резервного провайдера `[reserve]`. |
| `AI_RESERVE_API_KEY` | — | Ключ резервного провайдера. |
| `AI_RESERVE_MODEL` | `glm-5.3-flash-free` | Модель резервного провайдера `[reserve]`. |

Переменные окружения имеют приоритет над `.env`, флаги — над обоими.

```sh
go run ./app                            # веб-чат: сервер + браузер
go run ./app -cli                       # чат в терминале
go run ./app "Объясни, что такое горутина"
```

### Веб-интерфейс

При запуске без аргументов сервер поднимается на `http://127.0.0.1:5190` и
открывается в браузере. Если порт занят — берётся следующий свободный.
Сервер слушает только `127.0.0.1`.

Слева — панель «Настройки»:

- **Модели** — переключение основной и резервной модели.
- **Таймаут** — ползунок 10–60 с.
- **Способы решения** — флажки способов (Прямой ответ, Пошаговое решение,
  Через промпт, Эксперт). Выбор «Эксперт» разблокирует список экспертов.
- **Эксперты** — Математик / Философ / Критик (можно несколько).

Справа — рабочая область:

- **Решения** — две вкладки (`Рассуждение: low` и `Рассуждение: high`),
  каждая со своей таблицей результатов. Кнопка «Запустить решение» запускает
  выбранные способы для обоих уровней рассуждения.
- **Вывод** — после завершения всех запусков модель анализирует результаты и
  формирует итоговое заключение.

## Как это работает

Клиент отправляет `POST {AI_BASE_URL}/chat/completions` с телом в формате
OpenAI Chat Completions. В `messages` может подставляться персона эксперта
(системное сообщение) и директива уровня рассуждения: `low` — лаконичный ход
решения, `high` — максимально подробный (директива задаётся в промпте, так как
поле `reasoning_effort` у большинства моделей GPUStack не меняет результат).
Для метода *Через промпт* модель сначала составляет промпт, затем решает по
нему.

`POST /api/solve` выполняет один запуск: принимает `{method, expert,
condition, expected, timeout, reasoning}`, ограничивает его таймаутом (10–60 с)
и возвращает `{method, expert, name, tokens, duration, success, timed_out,
solution, prompt, reason, error}`. Успех определяется гибким сравнением ответа
с ожидаемым (`answersMatch`).

`POST /api/conclusion` собирает все результаты и возвращает `{analysis}` —
содержательный вывод модели по затратам ресурсов, сравнению методов и
рекомендации.

Страница (`go:embed`) строит таблицы, вкладки и вкладку «Вывод», отправляя
запросы в API и отрисовывая ответ с лёгким Markdown-парсером
(`renderMarkdown`), включая таблицы и LaTeX-формулы.

## Безопасность

- `.env`, `.idea/` и `bin/` уже в корневом `.gitignore` — правило действует
  для всех папок задач, поэтому секреты и артефакты не попадают в репозиторий.
- Не передавайте ключ флагом `-api-key` в общих системах: он остаётся в
  истории shell.
- Ключ и переписка не пишутся на диск; детали запроса/ответа хранятся только
  в памяти и отдаются в панель «Детали», сам ключ в них не попадает.
