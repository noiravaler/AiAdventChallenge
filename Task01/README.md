# ai-chat-go

Чат с ИИ через OpenAI-совместимый API с веб-интерфейсом в стиле плоского мессенджера (бирюзовая тема). Написан на Go без внешних зависимостей: только стандартная библиотека.

## Возможности

- Веб-чат в браузере: при запуске поднимается локальный сервер и открывается страница в стиле мессенджера.
- Потоковый вывод ответа (SSE) прямо в окно чата.
- История диалога на сервере, кнопка «Новый диалог» (очистка истории).
- JSON-лог API-запросов и ответов в консоли приложения.
- Терминальный режим (`-cli`) и разовый запрос из командной строки.
- Системный промпт.
- Любой OpenAI-совместимый сервер: OpenAI, DeepSeek, OpenRouter, Groq, Ollama, LM Studio и т.д.
- Конфигурация через переменные окружения, файл `.env` или флаги.

## Требования

- Go 1.22 или новее.

## Быстрый старт

```sh
cd ai-chat-go
cp .env.example .env
# откройте .env и впишите AI_API_KEY
go run .
```

Или без файла `.env`:

```sh
export AI_API_KEY="sk-..."
go run .
```

Разовый запрос:

```sh
go run . "Привет! Кто ты?"
```

## Настройка

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AI_API_KEY` | — | API-ключ. Не нужен для локального сервера. |
| `AI_BASE_URL` | `https://api.openai.com/v1` | Базовый URL API (без `/chat/completions`). |
| `AI_MODEL` | `gpt-4o-mini` | Имя модели. |
| `AI_SYSTEM` | — | Системный промпт. |
| `AI_TIMEOUT` | `5m` | Таймаут одного запроса, например `90s`. |
| `AI_MAX_TOKENS` | `0` | Максимум токенов ответа, `0` — на усмотрение провайдера. |

Переменные окружения имеют приоритет над `.env`, флаги — над обоими.

### Примеры провайдеров

| Провайдер | `AI_BASE_URL` | `AI_MODEL` (пример) |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenRouter | `https://openrouter.ai/api/v1` | `openai/gpt-4o-mini` |
| Groq | `https://api.groq.com/openai/v1` | `llama-3.3-70b-versatile` |
| Ollama (локально) | `http://localhost:11434/v1` | `llama3.2` |
| LM Studio (локально) | `http://localhost:1234/v1` | имя загруженной модели |

Для локальных серверов ключ можно не указывать.

## Использование

```sh
go run .                            # веб-чат: сервер + браузер
go run . -cli                       # чат в терминале
go run . "Объясни, что такое горутина"
go run . -model gpt-4o "Скажи что-нибудь"
go run . -no-stream "Ответь одним абзацем"
go run . -system "Отвечай только по-русски"
```

### Веб-интерфейс

При запуске без аргументов клиент поднимает сервер на `http://127.0.0.1:5190`
и открывает его в браузере (дизайн — бирюзовый мессенджер с пузырями
сообщениями, как на референсе chatme.ai). Если порт занят,
берётся следующий свободный. Сервер слушает только `127.0.0.1`, переписка не
покидает компьютер. Страница умеет:

- отправлять сообщения (Enter или кнопка с бумажным самолётиком);
- показывать ответ по мере поступления токенов;
- «Новый диалог» (кнопка «+» в шапке) — очистить историю на сервере;
- после перезагрузки страницы история восстанавливается (`GET /api/history`).

Чтобы браузер не открывался автоматически, добавьте `-no-open`.

### Флаги

| Флаг | Описание |
|---|---|
| `-base-url` | Базовый URL API. |
| `-api-key` | API-ключ (лучше через `AI_API_KEY`, чтобы ключ не попал в историю команд). |
| `-model` | Имя модели. |
| `-system` | Системный промпт. |
| `-max-tokens` | Максимум токенов ответа. |
| `-timeout` | Таймаут запроса, например `2m`. |
| `-no-stream` | Не использовать потоковый вывод. |
| `-web` | Веб-интерфейс с открытием в браузере (по умолчанию `true`). |
| `-cli` | Терминальный чат вместо веб-страницы. |
| `-port` | Порт веб-интерфейса (по умолчанию `5190`). |
| `-no-open` | Не открывать браузер автоматически. |

`ai-chat -h` покажет справку.

### Команды в терминальном режиме (`-cli`)

| Команда | Действие |
|---|---|
| `/help` | Показать справку. |
| `/reset` | Очистить историю диалога. |
| `/model` | Показать текущую модель. |
| `/model <имя>` | Переключить модель. |
| `/system` | Показать системный промпт. |
| `/system <текст>` | Задать системный промпт и очистить историю. |
| `/exit`, `/quit` | Выйти. |

## Как это работает

Клиент отправляет `POST {AI_BASE_URL}/chat/completions` с заголовком
`Authorization: Bearer <AI_API_KEY>` и телом в формате OpenAI Chat Completions.
В потоковом режиме ответ читается как Server-Sent Events: строки `data: {...}`
разбираются, из `choices[].delta.content` собирается текст, `data: [DONE]`
завершает поток.

Веб-интерфейс работает так: браузер шлёт `POST /api/chat` с JSON
`{"message": "..."}`, сервер вызывает API и пересылает токены ответа в тело
HTTP-ответа по мере поступления; страница читает поток через
`ReadableStream` и дорисовывает текст в реальном времени. История хранится в
памяти сервера и отдаётся через `GET /api/history`.

Каждый вызов API логируется в консоль приложения (stdout) построчно в формате
JSON: объект `{"type":"request", ...}` с URL и телом запроса перед отправкой и
объект `{"type":"response", ...}` с текстом ответа (или полем `error`) после
завершения.

## Безопасность

- `.env`, `.idea/` и `bin/` уже в `.gitignore` в корне проекта — это правило действует для всех папок задач (Task01, Task02, ...), поэтому секреты и артефакты не попадают в репозиторий.
- Не передавайте ключ флагом `-api-key` в общих системах: он остаётся в истории shell.
- Приложение не пишет ключ и переписку на диск; JSON-лог запросов и ответов
  выводится только в консоль (stdout), сам ключ в лог не попадает.
