# ai-chat-go — Task04

Веб-приложение для **исследования поведения модели** при решении задач через
OpenAI-совместимый API, написанное на Go без внешних зависимостей (только
стандартная библиотека).

> Task04 — приложение для сравнения **повторных прогонов при разных
> температурах** на двух задачах: одна с проверкой ответа, вторая — без
> (генеративная). Результаты сводятся в таблицу-матрицу и анализируются в
> двух блоках вывода.

## Возможности

- **Две задачи рядом** — слева блок выбора модели, правее два блока задач
  (`Задача 1` и `Задача 2`). Задачи задаются прямо в интерфейсе (текст поля
  только для чтения).
- **Выбор модели** — блок «Модель» слева: полносписочный список чат-моделей
  (получается из `GET /api/models`) плюс, при наличии, резервная модель
  `[reserve]`. Клик по модели переключает её через `POST /api/model`; список
  при этом сохраняется целиком.
- **Матрица «Результаты»** — для каждой задачи таблица `3 × 6`: 3 строки
  (`Температура 0`, `Температура 0.7`, `Температура 1.2`) по 5 ячеек на
  строку. На каждую температуру выполняется **5 запросов**, результат каждого
  попадает в отдельную ячейку. Заголовков у таблицы нет.
- **Цветовая индикация** — для `Задачи 1` (с ожидаемым ответом) зелёная ячейка
  (`.ok`) если ответ совпадает с ожидаемым, иначе красная (`.fail`). Для
  `Задачи 2` (генеративной) валидация отключена — ячейки показывают только
  текст ответа без окраски.
- **Проверка ответа для задачи 1** — сравнение через `answersMatch`: допускает
  разные написания, LaTeX-символы (`\frac`, `\Rightarrow`), дроби и
  эквивалентные значения; для текстовых ответов — совпадение значимых слов.
- **Блок «Вывод» (на каждую задачу)** — после завершения прогонов задачи
  модель анализирует ответы на **3 вопроса**:
  1. насколько ответы отличаются между прогонами при одинаковых параметрах;
  2. сколько раз сломался формат или ответ оказался неверным;
  3. где разнообразие полезно, а где вредит.
- **Блок «Общий вывод»** — после обеих задач модель анализирует все ответы и
  отвечает на два вопроса: для каких задач подходит каждая настройка и даёт ли
  `temperature = 0` одинаковый ответ каждый раз.
- **Повтор при ошибке/таймауте** — каждый запрос к модели выполняется до
  **3 попыток** (`MAX_ATTEMPTS`), с паузой 250 мс между ними, если ответ упал
  с ошибкой или по таймауту.
- **Прогресс-бар** — одна общая полоса хода на обе задачи (30 запросов на
  задачу), кнопка «Выполнить» блокируется на время прогона.
- **Лимит токенов** — `max_tokens` для таблицы «Результаты» ограничен **15000**
  (для `/api/solve` и выводов — 20000), таймаут одного запроса по умолчанию
  **30 с** (1–60 с).
- **Локальный сервер с `go:embed`** — страница встроена в бинарник, поэтому
  любые правки `static/index.html` требуют пересборки.

## Настройка

| Переменная | По умолчанию | Описание |
|---|---|---|
| `AI_API_KEY` | — | API-ключ. Не нужен для локального сервера. |
| `AI_BASE_URL` | `https://api.openai.com/v1` | Базовый URL API (без `/chat/completions`). |
| `AI_MODEL` | `gpt-4o-mini` | Имя основной модели. |
| `AI_MODELS` | `DefaultModels` | Явный список моделей для блока «Модель» (фолбэк). |
| `AI_SYSTEM` | — | Системный промпт. |
| `AI_TIMEOUT` | `5m` | Таймаут одного запроса, например `90s`. |
| `AI_MAX_TOKENS` | `0` | Максимум токенов ответа; `0` → 20000. |
| `AI_RESERVE_BASE_URL` | `https://opencode.ai/zen/v1` | Базовый URL резервного провайдера `[reserve]`. |
| `AI_RESERVE_API_KEY` | — | Ключ резервного провайдера. |
| `AI_RESERVE_MODEL` | `glm-5.3-flash-free` | Модель резервного провайдера `[reserve]`. |

Переменные окружения имеют приоритет над `.env`, флаги — над обоими.

### Веб-интерфейс

При запуске без аргументов сервер поднимается на `http://127.0.0.1:5190` и
открывается в браузере. Если порт занят — берётся следующий свободный.
Сервер слушает только `127.0.0.1`.

Сверху (слева направо):
- **Модель** — список доступных чат-моделей (основные + `[reserve]`); клик
  переключает модель, список не схлопывается.
- **Задача 1** — текст логической задачи про высказывания А/Б/В и поле
  «Ожидаемый ответ» (проверяется на правильность).
- **Задача 2** — текст задания (сгенерировать название книги); поле ответа
  отсутствует, правильность не проверяется.

Ниже:
- **Кнопка «Выполнить»** с общим прогресс-баром — запускает прогоны обеих
  задач последовательно (по 15 запросов на задачу: 3 температуры × 5).
- **Вкладки «Задача 1» / «Задача 2»** — переключают панели результатов и
  выводов.
- **Результаты** — таблица-матрица (3 температуры × 5 прогонов); зелёный/красный
  цвет ячеек для задачи 1 в зависимости от совпадения ответа.
- **Вывод** — анализ прогонов выбранной задачи по трём вопросам.
- **Общий вывод** — анализ всех ответов по обеим задачам (какая настройка
  подходит для какой задачи; одинаков ли ответ при `temperature = 0`).

## Как это работает

Клиент отправляет `POST {AI_BASE_URL}/chat/completions` с телом в формате
OpenAI Chat Completions. Системное сообщение — «Отвечай кратко: назови только
итоговый ответ». В запрос всегда передаётся `temperature` (включая `0`) и
`max_tokens` (15000 для таблицы результатов).

`POST /api/run` выполняет один запуск: принимает `{condition, expected,
temperature, timeout}` и возвращает `{answer, success, tokens, duration,
reason}`. Успех определяется гибким сравнением ответа с ожидаемым
(`answersMatch`).

`POST /api/run-conclusion` собирает результаты по одной задаче и возвращает
`{analysis}` — разбор по трём вопросам (отличия между прогонами, сбои формата,
польза/вред разнообразия).

`POST /api/general-conclusion` принимает результаты обеих задач и возвращает
`{analysis}` — общий вывод: какая настройка подходит для какой задачи и
одинаков ли ответ при `temperature = 0`.

`GET /api/models` возвращает `{current, models[], reserve, reserve_ready}` и
используется для блока выбора модели; `POST /api/model` переключает модель.

Страница (`go:embed`) строит матрицу результатов и блоки вывода, отправляя
запросы в API и отрисовывая ответы лёгким Markdown-парсером
(`renderMarkdown`), включая заголовки, списки и таблицы.

## Безопасность

- `.env`, `.idea/` и `bin/` уже в корневом `.gitignore` — правило действует
  для всех папок задач, поэтому секреты и артефакты не попадают в репозиторий.
- Не передавайте ключ флагом `-api-key` в общих системах: он остаётся в
  истории shell.
- Ключ и переписка не пишутся на диск; детали запроса/ответа хранятся только
  в памяти.
