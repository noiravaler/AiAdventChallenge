# Task20_MCP — Affirm MCP: отдельный сервер аффирмаций и перевода

Отдельный **MCP-сервер мелких добрых сервисов**: случайная аффирмация дня
(affirmations.dev) и перевод произвольного текста (бесплатный эндпоинт
Google Translate, `client=gtx`) — оба без ключей. Функциональность
**вынесена из Task17_MCP** (orbit): там пакет `affirmations` обслуживал
инструмент `daily_affirmation` и использовался дневником (`journal_*`) и
подбором даты (`elect_*`), здесь он — ядро самостоятельного сервера.

Особенность задания: инструмент `daily_affirmation` **намеренно назван так
же, как в Task17_MCP** — при одновременном подключении обоих серверов к
чату возникает потенциальный конфликт имён, который хаб Task16/17/18/19/20
разрешает префиксом `slug__tool` (см.
[«Конфликт имён с Task17_MCP»](#конфликт-имён-с-task17_mcp)).

## Архитектура

```
Агент (Task16/17/18/19/20 / Claude Desktop / любой MCP-клиент)
   │  MCP: stdio ИЛИ Streamable HTTP (/mcp)
   ▼
affirm-mcp (Go 1.26, SDK modelcontextprotocol/go-sdk, без состояния)
   ├─ affirmations.dev            — аффирмация дня (без ключа)
   └─ Google Translate (gtx)      — перевод en→ru и в другие пары языков (без ключа)
```

Сервер полностью **без состояния**: оба инструмента — чистые вызовы внешних
API, ничего не накапливается и не персистится. Переводчик — вторичная
зависимость: его сбой не роняет `daily_affirmation` (вернётся оригинал на
английском), а вот недоступность affirmations.dev — роняет (это единственный
источник данных).

## Инструменты (3)

| Tool | Что делает |
| ---- | ---------- |
| `daily_affirmation` | аффирмация дня на русском (перевод Google gtx; при сбое — оригинал) + случайный волшебный смайлик ✨. **Имя совпадает с инструментом Task17_MCP** — намеренный потенциальный конфликт |
| `translate_text` | перевод произвольного текста через gtx; по умолчанию en→ru, направление задаётся аргументами `source`/`target` (коды языков) |
| `affirmation_status` | диагностика: доступность affirmations.dev и переводчика (аналог `orbit_status` в orbit) |

## Конфликт имён с Task17_MCP

В Task17_MCP (orbit) есть свой `daily_affirmation` — имя осталось занятым
после выноса аффирмаций: под ним теперь живёт **намеренный именной дубль
`synastry_compare`** (аффирмационный код из orbit удалён, дневник и цепочки
`elect_*`/`brief_*` аффирмацию больше не включают). Здесь инструмент
называется так же:

- по отдельности серверы не мешают друг другу;
- вместе в одном чате (`AI_MCP_URLS` хаба Task16/17/18/19/20) оба отдают
  инструмент с одним именем — хаб считает вхождения имени и всем
  дубликатам меняет имя на `slug__tool`:

```
orbit__daily_affirmation   ← от сервера orbit  (http://127.0.0.1:5199/mcp)
affirm__daily_affirmation  ← от сервера affirm (http://127.0.0.1:5200/mcp)
```

- уникальные имена (`translate_text`, `affirmation_status` и все остальные
  инструменты orbit) остаются без префикса;
- маршрутизация вызова по префиксу — в `mcpclient` чата
  (Task16+; `rebuildLocked`), так что модель видит оба инструмента и
  вызывает каждый на своём сервере без двусмысленности.

Это же поведение можно наблюдать в Claude Desktop: при двух stdio-серверах
инструменты разводятся по именам серверов, а не по именам инструментов.

## Запуск сервера

```sh
cd Task20_MCP
go run ./app                       # MCP over stdio
make run-http                      # http://127.0.0.1:5200/mcp + статус-страница http://127.0.0.1:5200/
make build                         # бинарник bin/affirm

make probe-affirmation             # go run ./app -probe daily_affirmation
make probe-translate               # -probe translate_text -args '{"text":"…"}'
make probe-status                  # -probe affirmation_status
```

Режимы совпадают с orbit: stdio (по умолчанию), `-http addr` (Streamable
HTTP `/mcp` + страница статуса), `-list`, `-probe tool -args '{…}'` для
отладки без MCP-клиента.

### Подключение к чату Task16 / Task17 / Task18 / Task19 / Task20

```sh
AI_MCP_URLS="orbit=http://127.0.0.1:5199/mcp,affirm=http://127.0.0.1:5200/mcp" go run ./app
```

Оба сервера стартуют одновременно; в чате появляются и `orbit__daily_affirmation`,
и `affirm__daily_affirmation` — тестовый вопрос «дай аффирмацию дня» покажет,
как модель выбирает между дубликатами.

В **Task20** affirm подключён по умолчанию, и чат сам поднимает сервер при
старте через `mcpboot` (проверка `/api/status`, запуск из
`AI_MCP_AFFIRM_DIR` — по умолчанию автодетект `../Task20_MCP`). В блоке
«MCP» у affirm есть кнопка остановки/подъёма процесса, независимая от
тумблера: «стоп» убивает процесс, но инструменты остаются у модели (вызовы
возвращают ошибку — симуляция отказа сервиса), «поднять» запускает сервер
заново. Группа блобов «Affirm» (фраза дня, перевод, статус) и группа
«Все MCP» со сценариями на все три сервера — в чате Task20.

### Подключение Claude Desktop (stdio)

```json
{
  "mcpServers": {
    "affirm": {
      "command": "go",
      "args": ["run", "./app"],
      "cwd": "/path/to/ai-chat-go/Task20_MCP"
    }
  }
}
```

## Конфигурация (`.env` / окружение)

| Переменная | По умолчанию | Что задаёт |
| ---------- | ------------ | ---------- |
| `AFFIRM_URL` | `https://www.affirmations.dev` | источник аффирмаций (без ключа) |
| `AFFIRM_TIMEOUT` | `10s` | лимит запроса аффирмаций и перевода |
| `AFFIRM_TRANSLATE_URL` | `https://translate.googleapis.com/translate_a/single` | эндпоинт перевода; пустое значение отключает перевод (только оригинал) |

Приоритет: флаги > окружение > `.env` — как во всех заданиях репозитория.

## Отличия от Task17_MCP

- Вынесены только сервисы аффирмаций и перевода (пакет `affirmations`);
  логика клиентов не менялась — добавлены публичный `Translate` (произвольная
  пара языков для `translate_text`) и `Status` (диагностика провайдеров).
- Никаких астро-движков, геокодинга, погоды, хранилищ и цепочек: сервер не
  имеет состояния и не пишет файлов.
- Три инструмента вместо двадцати трёх; `daily_affirmation` повторяет
  описание orbit дословно, чтобы конфликт имён был «честным» (одинаковое
  имя + одинаковое описание).

## Ограничения

- Бесплатный эндпоинт gtx не имеет SLA: возможны лимиты и паузы — на этот
  случай в `daily_affirmation` предусмотрен откат к оригиналу, а
  `affirmation_status` показывает фактическое состояние.
- Офлайн-тесты (`go test ./...`) не ходят в сеть: все внешние API
  подменяются `httptest`-серверами.
